web_fetch

Retrieve what a server sends, and return it as text. No browser, no scripts.

Most of what is asked for is already in the bytes: an API, a JSON endpoint, a raw file, a feed, a README, documentation, a changelog. For those, starting a browser costs seconds and hundreds of megabytes of memory to arrive at the same answer a single request already had.

A body that is not a document comes back exactly as it was served, because the point of fetching an API is its bytes. A document is flattened to text by the same code web_browse uses, so the same page reached either way reads the same.

It says when it was the wrong tool

This is the whole reason a cheap fetch is safe to offer. Its predecessor was a silent fallback inside the browser tool: with no browser installed, a page whose text had not been written yet came back as the shell it ships as, and whoever asked could not tell that from a page that simply says little (ADR-044).

So the shape is the same and the honesty is new. When a fetched document both runs scripts and has almost nothing to say without them, the result says so and names web_browse. The caller decides whether to spend a browser on it; nothing is substituted on their behalf.

The test is deliberately reluctant. A warning that fires on finished pages is a warning nobody reads, and it sends the reader to a tool that costs a hundred times as much to return the same thing. A page with no scripts is never questioned, and neither is a body that is not a document.

A status is part of the answer. A page that answers 404 or 500 is reported as a failure that names the code and carries the body the server sent. Hiding either would leave a caller unable to tell a missing page from an empty one.
Nothing here disguises the request. The agent identifies itself as what it is. There is no spoofed browser string, no cookie jar, and no retry through another route; a site that declines to serve the agent is reported as declining.

Acceptance criteria

  • A page whose text the server already sent is returned as text, without a browser being started.
  • A JSON or plain-text body is returned verbatim, not as flattened prose.
  • A document whose text is written by its scripts is returned with a note saying so and naming web_browse.
  • A page that is already readable is returned without that note, whether or not it runs scripts.
  • A response of 400 or worse is reported as a failure naming the status code and carrying the body that came with it.
