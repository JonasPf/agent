web_fetch

Fetch a URL and return the page's text.

What it does

Loads the URL and returns what a person would read. Where a headless browser is installed, the page is rendered: scripts run and the DOM settles first, so a page assembled on the client reads the same as it would in a window. A body that is not HTML — JSON, plain text — comes back verbatim rather than being stripped of markup it does not have.

ParameterMeaning
urlThe address to fetch. Required.

What is installed decides the path

One code path, chosen by whether a browser is present. With one, the page is rendered. Without one, the bytes are fetched over HTTP and a page that needs its scripts comes back as the shell it ships — thin, and honestly so.

This is not a fallback bolted on. The deployment the agent actually runs in has too little memory for a browser (ADR-038), so the unrendered path is the one in production. Returning a thin page is the right answer there; failing because a browser is absent would make the tool useless on the hardware it runs on.

Nothing here disguises the request. The browser is used as it comes. There is no spoofed agent string, no cookie jar, no retry through another route, and a site that declines to serve the agent is reported as declining. A tool that worked around refusals would be a tool whose behaviour the operator could not predict from what it says.

Limits

The response body is read up to two megabytes, and the text returned is capped at forty thousand characters. A page longer than that is cut, and the cut is reported.

Acceptance criteria

  • An HTML page returns its readable text, without markup.
  • A page whose content is assembled by scripts returns that content where a browser is available.
  • A non-HTML body is returned verbatim.
  • Where no browser is available the tool still fetches, and says the page was not rendered.
  • Text beyond the cap is truncated and the result says it was truncated.
  • A response body beyond the byte limit is read no further.
  • A refused or failed request reports the status and does not retry by another route.
  • An empty URL is refused.
