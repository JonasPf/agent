edit

Replace an exact string in a file in the session's working directory.

What it does

Finds an exact substring and replaces it. The match is literal: no patterns, no whitespace normalisation, no fuzzy matching.

ParameterMeaning
pathRelative to the session's working directory. Required.
oldThe exact string to find. Required, and may not be empty.
newWhat to put in its place. Required; may be empty, which deletes.
replace_allReplace every occurrence rather than refusing an ambiguous one. Optional.

Ambiguity is refused, not resolved

A string occurring more than once is an error unless replace_all was asked for. The failure says how many times it occurred and what to do about it.

This is the whole point of the tool. Replacing the first of several matches is the edit that appears to succeed and does the wrong thing — and it does it to the occurrence the caller was least likely to mean, since the one being aimed at is rarely the first. Refusing costs one round trip; guessing costs a corrupted file nobody looks at again.

CaseResult
old occurs onceReplaced.
old occurs more than once, no replace_allRefused, stating the count and naming both remedies: more context, or replace_all.
old occurs more than once, with replace_allEvery occurrence replaced; the count is reported.
old not foundRefused, naming the file.
old is emptyRefused. An empty match is every position in the file.

Acceptance criteria

  • A unique match is replaced and the file is otherwise byte-identical.
  • A string occurring more than once is refused unless replace_all is given, and the refusal states how many times it occurred.
  • replace_all replaces every occurrence and reports how many.
  • An old that does not occur is refused and names the file.
  • An empty old is refused.
  • An empty new deletes the matched text.
  • The result reports how many replacements were made.
  • A missing file fails and names the path.
  • A path that would resolve outside the session's working directory is refused.
