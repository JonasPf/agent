session_search

Full-text search across transcripts.

What it does

Queries a full-text index over every transcript entry ever written, and returns the session, the position, and a snippet for each match. Given a hit's number instead, it reads that one entry whole.

ParameterMeaning
queryWords to look for. Each matches as a prefix, and punctuation is looked for as written rather than read as query syntax. Required unless seq is given.
seqA hit's number. Reads that entry whole instead of searching: in this session, or in the one session names.
sessionWhere to look. Defaults to the current session. A session identifier searches that one; all searches every session.
limitMaximum matches. Optional; twenty by default.

It is what makes compaction safe

A compaction takes detail out of the context but not out of the index. What the agent can no longer see, it can still look up — so a conversation that has compacted ten times still has its whole history one deliberate call away.

That is the difference between compression and loss, and it is why this tool is not optional alongside compaction. An entry a compaction covers is still returned by a search of its own session.

A hit can be read whole

A hit is a dozen words around the match, which finds an entry and does not tell what it said. That was once all there was. A compaction hid the agent's own last answer, the operator replied "yes, I'll start that on Monday", and the agent spent four hours and 696 searches assembling that answer from snippets, each search adding a few words. So a hit's number reads the entry it names: who wrote it and when, its text, the calls it made, or what a tool returned, cut at twenty thousand characters. The result says when the entry is one a compaction folded away or a revert took back.

Reading follows the same scope as searching. With no session it reads the calling conversation; another conversation's entry is read only when its id is given, and all names no one conversation, so it is refused.

The default scope is this session. Searching one's own history is ordinary. Reading another conversation is a thing the operator should be able to watch being decided, so it is a scope the agent has to ask for, and asking appears in the transcript as the tool call it is. Since ADR-055 nothing crosses a session boundary unasked at all, which makes this the whole of the route between conversations.

Results

Each hit names its session and its position within it, so the operator can open the conversation at the line that matched. A query matching nothing says so rather than returning an empty body, which would read like a call that failed to run.

Acceptance criteria

  • A search with no scope given searches the current session and no other.
  • A search scoped to all returns matches from other sessions.
  • A search naming a session identifier searches that session.
  • An entry covered by a compaction is still returned by a search of its own session.
  • Each result identifies its session and position.
  • A query matching nothing reports that, distinguishably from a failure.
  • A query holding punctuation, or a word a full-text index reads as syntax — follow-up, notes.md, AND — is searched for as written, not refused.
  • An empty query is refused, unless a number is given to read.
  • A hit's number reads that entry whole, in the calling session or in the one named; a number that names no entry fails and quotes it.
  • Event entries are searchable.
  • Eval cases cover an unscoped search, a deliberate widening, and reading a hit whole.
