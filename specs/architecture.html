Architecture

One process, one container, one user.

Components

ComponentResponsibility
GatewayServes the HTTP API, the web UI, and a WebSocket stream. The only network surface.
Agent loopAssembles a request from a session, calls the model, dispatches tool calls, appends results, repeats until the model stops calling tools.
SchedulerTicks once per second. Fires due jobs into their sessions. Owns dead lettering and the circuit breaker.
Tool registryScans the tool directory, validates manifests, exposes schemas to the model, executes tools as subprocesses.
StoreSQLite for structured state and full-text search. JSONL files for transcripts.

All five run in one process. There is no message broker, no worker pool, and no inter-service protocol.

Storage

Transcripts are JSONL files on disk, one per session, appended to and never rewritten. They are the source of truth.

SQLite holds everything else: sessions metadata, jobs, dead letters, memory, tool state, push subscriptions, and a full-text index over transcript entries. Both the metadata and the index are derived from the JSONL files and can be rebuilt from them.

Why both. A transcript is an append-only log and belongs in a file. Everything else is queried, filtered, and joined, and belongs in a table. Rebuildability means a corrupt database costs a restart, not data.

Acceptance criteria

  • Deleting the SQLite file and restarting reconstructs all session metadata and search indexes from the JSONL transcripts.
  • SQLite runs in WAL mode.
  • No transcript entry is ever modified or deleted once written.
  • Tool tables are namespaced by a prefix declared in the tool's manifest.

Model access

All model calls go to OpenRouter over its OpenAI-compatible API. The model is selected per session and can be changed mid-session.

Three OpenRouter endpoints are consumed beyond inference:

EndpointUsed for
/modelsPopulating the model picker, context-window sizes, and per-token prices. Cached, refreshed daily. Models are filtered to those whose supported_parameters include tools.
/keyRemaining credit and usage totals shown in the UI.
/chat/completionsInference, streamed.

Prompt caching

Caching is not free. A cache write costs more than an ordinary read — 1.25x for a five-minute lifetime, 2x for an hour — so a prefix that is written and then read only once or twice costs more than not caching at all. Break-even is around three calls within the lifetime.

Long-lived sessions frequently sit below that. A session whose only job uses a deterministic check makes no model calls at all between firings, so caching it would double the cost of each isolated call.

The cache is therefore requested only when another call is expected before it expires.

Acceptance criteria

  • For providers requiring explicit cache breakpoints, the request carries a cache marker at the end of the stable prefix.
  • A cache write is requested only when a further call is expected within its lifetime: the user turned recently, or the session has a model-invoking job due sooner than the lifetime.
  • Active conversation requests the five-minute lifetime; a session with a frequent model-invoking job requests the hour.
  • An isolated call on an idle session requests no cache write.
  • Reported cached-token counts and cache discount are recorded per call and surfaced in the UI.
  • Providers that cache automatically receive no cache markers.

The container publishes no ports to the public internet. Tailscale Serve terminates HTTPS with a certificate valid for the tailnet hostname, which satisfies the browser's secure-context requirement for service workers and notifications.

Push notifications reach the phone through Apple's or Google's push service, which the gateway contacts outbound. Notification delivery therefore does not depend on the phone being on the tailnet.

Acceptance criteria

  • The container exposes no port reachable from outside the tailnet.
  • The web UI is served over HTTPS with a certificate the browser trusts without exception.
  • Notifications are delivered to the phone when it is not connected to the tailnet.
  • Opening a notification while off the tailnet fails visibly rather than showing a blank screen.

Process boundaries

The agent, its tools, and the gateway run as one user in one container. Tools the agent writes have the same access as the agent itself, including the model API key and the database.

The working directory is a git repository. Every tool reload commits the tool directory, so a tool that breaks the system is reverted rather than reconstructed.

Acceptance criteria

  • The workspace is a git repository with an initial commit created at first start.
  • A successful tool reload produces a commit containing the tool directory's current state.
  • Reverting to any commit and restarting yields a working system.

The tradeoff is recorded in ADR-004.
