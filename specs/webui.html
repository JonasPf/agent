Web UI

A phone-first interface. The laptop gets the same pages, wider.

See the rendered mock.

Installation

The interface is a progressive web app installed to the home screen. Installation is required rather than optional: on iOS, notifications are only delivered to installed web apps.

Acceptance criteria

  • The app is installable to the home screen on iOS and Android.
  • It launches without browser chrome once installed.
  • Opening it while off the tailnet shows a clear connectivity message, not a browser error.
  • Every control is operable one-handed on a phone.

Conversation view

The primary screen. A transcript, an input, and a status line.

ElementShows
Prompt entryFirst entry of the transcript. Persona, memory, skills index, and full tool definitions, each collapsible with a token count. Memory is editable.
MessagesUser and assistant turns, tool calls with their results.
EventsJob checks, summary updates, rotations, dead letters — one line each, visually quieter than messages.
AttributionAny message produced by a job names the job and links to it.
Status lineModel, context used against the window, tokens per second while streaming, session cost.

Acceptance criteria

  • Assistant output streams token by token.
  • Tokens per second is shown during generation and the final figure remains after it completes.
  • Context usage is shown against the session's rotation threshold, not the model's window.
  • The estimated cost of the next call is shown, and whether it will be cached.
  • Events are visually distinguishable from messages at a glance.
  • Long transcripts scroll to the newest entry without loading the entire history.
  • A tool call can be expanded to show its arguments and result.
  • Scrolling to the top of any conversation reaches the prompt entry.
  • Expanding the tool section shows every tool definition as the model receives it.

Session management

Acceptance criteria

  • All sessions are listed, newest activity first, with title, model, and unread count.
  • A session can be created, renamed, archived, and deleted.
  • Search finds text across all sessions and opens a result at its position.
  • The list shows which sessions have jobs attached.
  • A session can be forked, or rotated into a new session, in one action.
  • A session seeded from another links back to it, and the predecessor links forward.
  • Opening a link to an archived session lands on the live session of its chain and says so.
  • The rolling summary is viewable and editable from the session.

Per-session controls

Acceptance criteria

  • The model can be changed for a session, choosing from models that support tool calling.
  • The controls screen shows the session's fixed configuration, and offers a new one that takes effect by rotating.
  • Starting a conversation offers the same choice of model, tools, and skills, prefilled from the most recent session.
  • Toggling is available both when creating a session and while one is in progress.
  • A new session opens with the previous session's set, changeable before the first message.
  • Enable-all and disable-all act on the whole list in one tap.
  • Changes take effect on the next turn without restarting the session.
  • Disabling a tool that a job in this session depends on requires confirmation and names the job.

Files

Acceptance criteria

  • A file can be uploaded from a phone, including from the camera and the photo library.
  • An uploaded file is written to the workspace and referenced in the transcript by path.
  • Images are passed to models that accept them; other files are made available to the agent's file tools.
  • Upload progress is shown and a failed upload can be retried.
  • Files larger than 100 MB are refused before transfer begins.
  • Uploads are deleted with the session that referenced them.

Notifications

Two tiers, because a phone that buzzes for everything is a phone that gets ignored.

TierTriggerBehaviour
BadgeAny new assistant message in a session not in the foreground.Silent. Increments the count on the app icon.
InterruptThe agent calls the notify tool; or a dead letter; or the circuit breaker.A push notification with sound.

The agent decides what is worth interrupting for, and that decision is a visible tool call. Dead letters and the circuit breaker interrupt regardless, and this cannot be disabled.

Acceptance criteria

  • An interrupting notification carries its full text in the push payload and requires no network fetch to display.
  • Notifications are received when the phone is not on the tailnet.
  • Opening a notification navigates to the session and position that caused it.
  • Badge count reflects unread assistant messages and clears when the session is read.
  • A dead letter and a tripped breaker always interrupt.
  • Notifications can be muted per session, except the two that always interrupt.

Status and cost

Acceptance criteria

  • Remaining OpenRouter credit and usage are displayed and refreshed at least hourly.
  • Per-session cost is shown and derives from reported token usage and current model prices.
  • Cache hit rate is shown for sessions with jobs attached.
  • A tripped circuit breaker is visible from the session list without opening a session.

Panels

Jobs, dead letters, memory, tools, and skills each have a management panel. Tools that ship their own panel appear alongside them.

Acceptance criteria

  • Every job, dead letter, memory item, tool, and skill is viewable and editable without the agent.
  • A dead letter can be replayed or dismissed in one action.
  • Panels contributed by tools are listed with built-in panels and are visually consistent with them.
