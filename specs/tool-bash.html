bash

Run a shell command in the session's working directory.

What it does

Runs the command under /bin/sh -c, in the session's working directory, and returns standard output and standard error interleaved as one body — which is what a person reading a terminal sees, and what makes a diagnostic printed to stderr legible beside the output it explains.

It is a shell, so it does what it is told. Nothing in the tool inspects the command, refuses one, or decides what is safe. The boundary is the operating system's (ADR-039): the command can reach the session's own directory and the runtime, and is refused by the kernel everywhere else.

ParameterMeaning
commandThe shell command. Required.
timeout_secondsHow long to allow. Optional; the tool's own default is 120.

Two timeouts, and why

The registry kills a tool at the manifest's timeout_seconds, which for this tool is 150. The tool imposes its own, lower, at 120 by default. The gap is deliberate: a command that overruns is stopped by the tool, which is still alive and can say timed out after 120s. Were there only the outer limit, the subprocess would be killed with nothing written to stdout, and an overrun would be indistinguishable from a crash.

A caller may raise timeout_seconds, but the registry's limit still bounds it: asking for more than the manifest allows buys a kill rather than a message.

Limits

Output is capped at twenty thousand characters. A command that produces more has its output cut, and the cut is reported rather than silent — an unannounced truncation is a fact the model would reason from as though it were the whole answer.

A command that produces nothing says so. An empty body and a failed call must not look alike.

CaseResult
Empty or whitespace commandFails: command is required.
Non-zero exitFails, carrying the exit status and everything the command wrote.
Overruns the timeoutFails, naming the limit it passed.
Succeeds with no outputSucceeds, saying there was none.
Writes past the capSucceeds with the output cut, saying that it was cut and by how much.

Acceptance criteria

  • Standard output and standard error come back interleaved, in the order written.
  • A non-zero exit is a failure and carries what the command wrote, not only its status.
  • A command producing no output reports that it produced none, distinguishably from a failure.
  • Output beyond the cap is truncated, and the result says it was truncated and how much was dropped.
  • A command that overruns is stopped by the tool and reports the limit it passed.
  • The tool's own timeout is below the manifest's, so an overrun is always reported rather than killed.
  • The command runs in the session's working directory, and a relative path resolves inside it.
  • A command reaching outside the session's directory is refused by the sandbox, not by the tool.
