skill_read

Load the full text of a skill.

What it does

Returns a skill's body by name. This is the other half of the arrangement described in Skills: the prompt carries every skill's name and one-line description, and nothing more. The bodies are what this tool reaches.

A skill that is a folder (ADR-069) is read in two steps. Without a file, this returns SKILL.md's body and, after it, the path and size of every other file in the folder with the call that reads one. With a file, it returns that file exactly as stored. The procedure says when a reference is needed; the reference is read then, not with it.

ParameterMeaning
nameThe skill's name, as it appears in the prompt's index. Required.
fileOne of the skill's other files, by the path listed after its text. Left out, the skill itself is read.
Why the index is in the prompt and the bodies are not. A skill body is long. Putting every one in the prompt would spend the session's cheapest, most cacheable tokens on instructions that most conversations never need. Putting none of it there would leave the agent unable to know what exists. The index is the smallest thing that makes the rest reachable, and reading one is a visible call rather than an invisible inclusion.

The failure this tool has to guard against is not an unreadable skill but an unread one. In a month of use a skill was in front of the model for 40 of the 132 turns that added to a record it covered, and for 13 of the 46 that researched on the web. The one rule that said to read a skill sat in the middle of the persona's scheduling rules, the description said what the tool does and not when to call it, and nothing said that compaction folds a skill away like any other turn — so a conversation that had read one once went on, after its next compaction, as though it still knew it.

So three places now say when. The skills index opens with the rule. Each shipped skill's description starts with when to use it. And this tool's own description says to call it before the work rather than after, and again once the skill's text is no longer in the conversation. The description is the one of the three that reaches a conversation already under way, because a session's prompt is fixed when it starts and the tool list is not.

A name that is not a skill fails and says so. It does not return an empty body, which the model would read as a skill with no instructions in it and proceed on.

Acceptance criteria

  • A known name returns the skill's body in full, exactly as stored.
  • An unknown name fails and quotes the name given.
  • A skill that exists with an empty body fails rather than returning nothing.
  • An empty name is refused.
  • A name is matched as it appears in the prompt's index.
  • Only skills indexed in this session's prompt are readable from it, and so are only their files.
  • A skill that is a folder returns SKILL.md's body, then the path of each other file and how to read one; a skill of one file returns its body alone.
  • A file returns that file of the skill exactly as stored.
  • A file the skill does not have fails, quoting the path given and naming the files it does have.
  • The description says to read a skill before the work it covers, and again once compaction has folded its text away.
