packages

Find and install a program the image does not ship.

What it does

Given search, it lists the packages whose name or description matches every word, each with its name, version, and description. Given install, it installs the packages named and says, for each, the version, the path in the store, and the disk it took. Given neither, it lists what this conversation has installed.

Packages come from the stable Nix release, nixos-26.05 (ADR-072). Search reads the package list the release publishes, and an install takes the revision that list belongs to, so what a search finds is what an install gets. The agent checks for a newer revision at most once a day.

The agent installs, not the tool: the tool hands the names to the tool API, and the agent fetches the packages into its store. From the next tool call on, their programs are on the conversation's PATH, in bash and in its jobs' checks. Another conversation's PATH does not have them; it installs them too, and finds them already downloaded. The store lives on a volume of its own; when the agent starts, it roots every conversation's packages again, and fetches any the store no longer holds.

A release carries some programs in more than one major version, each its own package: ffmpeg_7-headless and ffmpeg_8-headless, python312 and python313. Name one when the version matters. Within a release a version only gets fixes.

The description says all of this, and that Python libraries come from pip, not from here. No skill repeats it.

A package is not removed from a conversation: one left on PATH costs nothing, and deleting the conversation frees it. The store has no screen of its own either. Each install is a tool result in its conversation, and the 2 GB rule keeps the disk from filling.

Acceptance criteria

  • A search returns the release's packages matching every word, with name, version, and description, and runs no Nix evaluation.
  • An install fetches the named packages from the revision the search list belongs to; the result names each one's version, store path, and disk taken.
  • An installed package's programs run in the conversation's bash and checks, under the sandbox, from the next call on.
  • Another conversation's PATH does not include what this one installed.
  • Called with neither parameter, it lists the conversation's installed packages.
  • A name the release does not have is refused, and the refusal names the closest names.
  • A package the binary cache does not hold is refused, and nothing is built.
  • An install that would leave less than 2 GB of disk free is refused before anything is downloaded, naming its size.
  • Two installs at once run one after the other.
  • A conversation's packages are still on its PATH after the agent restarts, fetched again if the store lost them.
