notes

Short freeform notes that outlive a conversation.

What it does

Keeps a list of short texts, added one at a time and listed newest first. Notes are not memory: they are never loaded into a prompt, and they influence nothing unless asked for.

ActionDoes
addAppends one note. Requires text.
listReturns recent notes, newest first.

What it is for

It is the demonstration that a tool may own storage. It declares a db_prefix, creates its tables from a schema.sql applied at load, and ships a panel that reads them back through the API — the full shape of a tool with state, in the smallest thing that needs one.

Notes are not memory, and the distinction is load-bearing. memory is capped, curated, and in every prompt; a note is uncapped, unreviewed, and in none. So a note costs nothing until it is read, and never changes an answer the agent gives without being asked. Anything that should shape behaviour belongs in memory.

A note records which session wrote it, and listing is not filtered by session: notes outlive the conversation that wrote them, which is the whole reason they are not simply written to a file in the session's working directory.

Acceptance criteria

  • add appends a note and confirms it was stored.
  • add with empty text is refused.
  • list returns notes newest first.
  • list on an empty store says it is empty rather than returning nothing.
  • A note records the session that wrote it.
  • Listing is not scoped to a session; a note written in one conversation is listed in another.
  • Notes never appear in any system prompt.
  • The tool's tables all begin with its declared prefix.
  • The interface panel reads the tool's own tables through the API rather than the database directly.
