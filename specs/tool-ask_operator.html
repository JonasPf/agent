ask_operator

Stop and ask the operator for what a chat reply handles badly, on a screen made for it.

Why it exists

Some answers do not fit in a chat: a choice that has to be seen, ten answers at once, a script whose words and timing need correcting before money is spent on it. The agent can write a page for any of these, and until now had no safe way to show one and get something back. See ADR-074.

It is for a choice between options, several answers at once, approving or changing a plan, list, table, or script before something costly or hard to undo, feedback on a mockup or design, and a choice that has to be seen. A question that fits in a sentence belongs in a reply, and a finished report is a link to its file.

How it works

  1. The agent calls the tool with a message saying what it needs and why, and either questions or a page.
  2. The tool records the ask in asks/<id>.json in the working directory, and returns a link to its panel, #toolpanel/ask_operator/<session>/<id>.
  3. The agent puts the link in its reply and ends its turn. The transcript also offers the link as an Open button on the tool's result. Nothing waits in the call.
  4. The panel names the conversation, shows the message, and warns where an answer goes. It draws the form, or runs the page in a box.
  5. The operator presses Send or Decline, and the panel posts their answer as an ordinary message, which starts the next turn. Leaving the screen sends nothing.
ParameterMeaning
messageWhat is needed and why. Required.
questionsA form, as a list. Each has a name, a type of text, long_text, number, yes_no, choice, or choices, and optionally a label, options, default, and required.
pageAn HTML file in the working directory, at most 16 MB, holding everything it needs.

What a page can do

CallWhat it does
ask.answer(text)Proposes an answer. It is shown on the screen, and goes nowhere until Send.
await ask.save(name, text)Saves a file of up to 900 KB beside the page, and returns its path. The answer names every file saved.

A page has no origin and no network. It cannot use the operator's login, load anything from elsewhere, or reach a file by its address, so it embeds what it shows.

A page cannot answer for the operator. The agent writes the page, and the page is often how the agent asks for approval, so a page able to send would be able to approve itself. Send and Decline are in the panel, outside the box.

Acceptance criteria

  • An ask with no message, with neither questions nor a page, or with both, is refused and says why.
  • A page that is missing, outside the working directory, not .html, or over 16 MB is refused.
  • Questions of an unknown type, with a repeated name, or a choice with no options are refused.
  • An accepted ask is recorded in the working directory and returns a link to this conversation's panel.
  • The screen names the conversation asking, shows the message, and warns that what is entered reaches the agent and its model.
  • A page runs, and can propose an answer and save a file, but cannot reach the agent or the network.
  • A page saves only in its own folder; a name that climbs out is refused.
  • Nothing reaches the conversation until Send or Decline is pressed, and a page cannot press either.
  • A required answer holds Send back and says what is missing.
  • An answer says what was asked and that it was answered, with each value, the page's proposal, the files saved, and any note.
  • Decline says so, needs no answer, and carries a reason if one was given.
  • A tool result holding a panel link shows an Open button, in sight while the result is folded.
