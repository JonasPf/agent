Skills

A skill is a document that teaches the agent how to do one thing. It is prose, not code.

Skills are how the agent accumulates competence. A tool adds a capability; a skill adds judgement about when and how to use one.

Progressive disclosure

Only the name and description of each skill appear in the system prompt. The agent loads a skill's full text when it judges the skill relevant.

This is what allows the collection to grow. Twenty skills cost a few hundred characters of context rather than twenty documents' worth.

Acceptance criteria

  • The system prompt lists every enabled skill's name and description and no skill's body.
  • A skill's description is a single line.
  • Reading a skill is a tool call visible in the transcript.
  • Adding a skill requires no restart.
  • A skill with malformed frontmatter is skipped, and the failure is visible in the interface.

Self-authoring

The agent writes skills. After completing work that required figuring something out, it records what it learned so the next attempt starts from the answer.

Skills are the safe half of self-improvement: a poor skill is poor prose, whereas a poor tool is an executable that fails at three in the morning. Where a lesson can be written as a skill rather than built as a tool, it should be.

Acceptance criteria

  • The agent can create, edit, and delete skills.
  • Every skill is readable and editable in the interface.
  • Reading a disabled skill returns an error result; the skill stays listed in the prompt.
  • Skills are stored as files in version control, not in the database.
