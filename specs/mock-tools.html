›How a tool call worksfour steps
  1. OfferEvery model call lists the tools: each one's name, description and parameters, in the standard OpenAI format. That is all the model knows about a tool. 
    {"type": "function", "function": {"name": "web_search", "description": "Search the web…", "parameters": {…}}}
  2. CallThe model answers with a tool call instead of text: a name, and arguments as JSON. 
    {"id": "call_7", "function": {"name": "web_search", "arguments": "{\"query\": \"Go 1.25\"}"}}
  3. RunThe agent starts tools/web_search/run inside the sandbox below. The arguments go in on standard input; the tool answers on standard output, or is stopped at its timeout. 
    stdin   {"query": "Go 1.25"}
stdout  {"ok": true, "content": "1. Go 1.25 Release Notes …"}
  4. ReturnThe answer is saved to the transcript and sent back to the model as a tool message. The model then answers, or calls another tool.
A manifest has two parts. name, description and parameters are the standard part: they are what step 1 sends. The agent block is this agent's own: the timeout, the table prefix, and what the sandbox adds. It is read by the agent and never sent to the model.
