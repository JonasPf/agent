keeping-records

This skill ships with the agent. It is read-only here; copy it under another name to write your own.

Front matter ships with the agenton by default

Use when the operator asks you to remember, note, or keep track of anything — a fact, a preference, a decision, a list, a measurement, a symptom, an appointment — or asks about something kept earlier: how to keep it as files in this session's working directory, dated from clock, and read it back with a command.

The line every conversation's prompt carries. The agent decides from it alone whether to open the rest.

namekeeping-recordsdefaultonfiles1size6.4 KB

You have no memory but the files you write. The conversation is the wrong place for anything worth keeping — a transcript is folded away by compaction, and a thing you have to go back and search for is a thing you will get wrong. So "remember this", "note that", "keep track of", "add it to the list" all mean the same: write it to a file in this turn, and read it back from the file when it is asked about.

What is kept takes one of three shapes:

It isIt goes inFor example
a series: the same thing observed again and again, each time with a datelog/<stream>.csva weight, a test result, a symptom, a bill, a mood
a list: items to remember, with no date of their ownlists/<name>.mdbooks to read, gift ideas, safe foods, to-dos
a note: a fact, a preference, a decision, an account of what happenednotes/<topic>.mdthe car's tyre size, what the GP said

The date comes from clock, every time

Before you write anything that carries a date or a time, call clock in the same turn. Every row in a series, every appointment, every note that says when something happened — and every "today", "yesterday", "this morning", or "last night" the operator says, which means nothing until it is resolved against the clock.

Then let the shell write the date, so the row cannot disagree with the clock:

echo "$(date +%F),weight,81.2,kg,after breakfast" >> log/weight.csv
echo "$(date -d yesterday +%F),sleep,6.5,h," >> log/sleep.csv

Layout

INDEX.md            what is kept here: every stream, list, and note
log/<stream>.csv    date,metric,value,unit,note
lists/<name>.md     one item per line, each starting "- "
notes/<topic>.md    narrative and facts

Front matter yoursoff unless chosen

Use when the operator plans a trip or asks what to pack — build the itinerary, check it against the calendar, and keep the packing list in the working directory.

The line every conversation's prompt carries. The agent decides from it alone whether to open the rest.

nametrip-planningdefaultofffiles3size3.1 KB

What skill_read returns first, with the names of the other two after it.1.4 KB

A trip is three things kept apart: the itinerary, which changes; the packing list, which is mostly the same every time; and the bookings, which are facts. Keep each where it belongs.

Before anything else

  1. Get today's date from clock. Every "next Friday" is counted from it.
  2. Read packing.md with skill_read before writing the list.
  3. Start the list from checklist.csv, then add what this trip needs.

The itinerary

One day per heading in notes/trip-<place>.md, with the date in YYYY-MM-DD.
